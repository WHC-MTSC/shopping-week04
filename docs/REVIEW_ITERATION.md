# AWS 수집·PC 배포·재학습 실습 검증

2026-11-09에 수행한 기록입니다. 실제 AWS 검증과 합성 단위 테스트를 구분합니다. 과거 데이터 실습은 사용자가 명시적으로 선택했습니다.

## 실제 AWS와 데이터

- MFA 등록 후 새 로그인 세션으로 CLI `workload` 프로필의 인증을 확인했습니다.
- 서울 리전에 `/shopping-week04/workload` 그룹과 `pc-local` 스트림을 만들고 예측·정답 이벤트를 전송했습니다. IAM 정책·사용자·키는 만들지 않았습니다.
- [실제 읽기 검증](evidence/cloudwatch-live-check.json)은 AWS에서 같은 event_id와 전체 JSON 본문을 다시 읽어 대조한 결과입니다. [AWS 콘솔 화면](evidence/cloudwatch-live-events.jpg)도 캡처했습니다.
- 과거 336시간의 입력과 원본 CSV 정답을 HTTP API로 제출했습니다. 모든 기록은 `demo`이며 팀원 행동이나 새로운 운영 관측으로 표시하지 않았습니다. [재생 출처](evidence/practice-replay-summary.json)
- 원격 680개 이벤트를 내려받아 명시적 정답 336행과 행동·보상 337행을 만들었습니다. 같은 입력 1행은 지도 데이터에서 중복 제거하고, 배포 진단 중 정답을 입력하지 않은 6건은 격리했습니다. [다운로드 manifest](evidence/practice-export.json), [전처리 요약](evidence/practice-preparation.json)

## 후보 모델 판단

앞쪽 268행만 학습하고 뒤쪽 68행으로 기존·후보 모델을 비교했습니다. 같은 목표 시각은 학습·평가에 나누지 않았습니다. JSON 모델과 scikit-learn의 최대 확률 차이는 `2.66e-15`였습니다.

| 지표 | 기존 모델 | 실습 후보 |
|---|---:|---:|
| 정확도 | 0.9412 | 0.9118 |
| Macro F1 | 0.8283 | 0.7768 |
| 혼잡 재현율 | 0.6667 | 0.5000 |

후보 `practice-ef3126f6d608b314`는 성능 기준 미달이며 `historical_replay`, `promotion_eligible=false`입니다. [비교 보고서](../artifacts/practice-report.json)와 [후보 JSON](../artifacts/practice-model.json)을 참고용으로 보존했습니다. 기존 `artifacts/model.json`과 원래 평가 결과는 변경하지 않았습니다.

후보의 current 릴리스 전환 명령은 자동 승인 검토에서 차단됐으며 상세 사유는 제공되지 않았습니다. 같은 전환을 우회하지 않고, 별도 localhost 8003·별도 로컬 DB에서 후보를 실행하여 [모델 SHA·예측 검사](evidence/practice-model-check.json)와 [용도·버전 메타데이터](evidence/practice-serving.json)를 확인한 뒤 임시 서버를 종료했습니다. 최종 PC 서비스는 기존 모델을 사용합니다.

## 독립 리뷰에서 수정한 문제

- S3 검증기가 API 응답과 저장 이벤트의 전체 예측 응답을 비교하도록 보완했습니다. 보고서 쓰기 실패도 성공으로 출력하지 않습니다.
- CloudWatch 수락 상태를 S3·모사 상태와 별도로 관리합니다. 거절 이벤트는 대기 상태를 유지하고, 대상 그룹·스트림·리전이 다른 DB 재사용은 차단합니다.
- 전처리에서 확률 argmax와 다른 예측 단계, 같은 입력의 실제 정답과 모순되는 T/F 기록을 격리합니다.
- 인증 제공자가 멈춰도 실행·검증 CLI가 무한 대기하지 않도록 시간 제한을 보완했습니다.
- 실제 Windows 배포에서 단일 파일의 reparse-point 오인, venv 자식 콘솔 프로세스 오인, 비어 있는 환경 변수 복원 문제를 수정했습니다.
- PID 재사용 시 다른 프로세스를 종료하지 않고 기존 실행 기록을 만료 처리합니다. MSIX 가상화를 피하도록 설치를 현재 사용자 Documents 폴더에 둡니다.
- 최종 교차 리뷰에서 후보 배포가 평가 보고서를 확인하지 않는 문제를 수정했습니다. 모델·보고서의 용도, SHA·버전, 정확한 boolean 품질·승격 조건을 설치 변경 전에 검사하며, 실습 후보는 거절합니다. 11개 거부 사례와 허용 메타데이터 검사가 격리 환경에서 통과했습니다.
- 셸의 `WORKLOAD_MODEL_PATH`가 배포 품질 검사에 섞이지 않도록 기준 모델 경로를 고정하고 원래 환경을 복원합니다. README의 과거 CloudWatch 미구현 안내도 현재 상태로 고쳤습니다.
- 첫 Windows CI에서 자식 인터프리터 종료와 부모 실행기 종료가 겹치는 문제를 발견했습니다. 자식 종료 뒤 부모가 자연 종료할 시간을 최대 2초 주고, 남아 있는 프로세스에는 기존 소유권 검사를 적용합니다. 자연 종료·부모 생존·PID 재사용의 격리 회귀 검사를 추가했습니다.

Python 252개와 Node 29개 검사가 통과했고 Ruff·형식·BasedPyright도 통과했습니다. Windows 스크립트는 설치한 릴리스에서 필수 검사를 다시 실행하고 실제 HTTP 모델 검증 후 전환합니다. CI는 같은 모델의 설치·재시작·업데이트·롤백을 자동 검사합니다.

사용자 PC에서 두 릴리스의 배포·정지·시작·롤백과 저장된 자동 시작 명령의 실행을 확인했습니다. [최종 복구 상태](evidence/pc-baseline-restored.json)는 기존 모델 `77f4c9c1af34`, 자동 시작 등록 및 설치 스크립트 일치, CloudWatch 대기·실패 0건을 기록합니다. PC를 재부팅한 검사는 아닙니다. [PC 서비스의 원격 로그 대조](evidence/pc-cloudwatch-check.json)도 통과했습니다.

팀원이 직접 수행한 개별 테스트는 이번 자동 재생과 별개입니다. 로컬 브라우저 접근 제한으로 사용자 화면의 새 실습 배너는 브라우저에서 시각 검증하지 못했으며, 정적 자산·API·입력 계약 검사를 수행했습니다. 실제 CloudWatch 콘솔 캡처는 로컬 모사 화면이 아닙니다.

최종 독립 리뷰에서 원본 CSV·원격 내보내기·전처리 데이터·기존/후보 모델의 SHA와 68행 평가 지표를 재계산하여 일치를 확인했습니다. 팀원 직접 테스트는 사용자 요청에 따라 이번 마무리와 별도로 두며 [전달용 안내](TEAM_TESTING.md)를 제공합니다.
