# 팀원이 직접 수행할 인수 시험

처음 받은 팀원은 [설치·실행 안내](GETTING_STARTED.md)의 도구 설치, `feature/service-handoff` 브랜치 받기, 독립 배포 순서부터 진행합니다. 기본 `main`에는 전달 기능이 아직 없을 수 있습니다. **2026-11-16 기준 신규 팀원의 직접 배포·사용 결과는 미완료**이며, 아래 서식은 실행한 사람이 채웁니다.

각자 자신의 Windows PC에서 `Hourahead-TeamTest` 설치 폴더와 **http://127.0.0.1:18001/** 를 사용합니다. `127.0.0.1`은 접속한 PC 자신을 가리키므로 다른 사람의 서버에 연결되지 않습니다. 원격 공유 서비스는 이 시험의 범위가 아닙니다.

## 자동 API 검사와 재시작 확인

저장소 루트에서 실행합니다. 첫 배포는 `local` 모드이며 AWS 인증·권한이 필요하지 않습니다.

```powershell
$teamInstallRoot = "$env:USERPROFILE\Documents\Hourahead-TeamTest"
.\scripts\deploy-local.ps1 -Action Deploy -InstallRoot $teamInstallRoot -Port 18001 -Backend local
.\scripts\verify-service.ps1 -BaseUrl http://127.0.0.1:18001 -OutputPath runtime/acceptance.json
.\scripts\deploy-local.ps1 -Action Stop -InstallRoot $teamInstallRoot -Port 18001
.\scripts\deploy-local.ps1 -Action Start -InstallRoot $teamInstallRoot -Port 18001
.\scripts\verify-service.ps1 -BaseUrl http://127.0.0.1:18001 -PreviousReport runtime/acceptance.json -OutputPath runtime/persistence.json
```

두 보고서가 모두 `status=passed`인지 확인합니다. 첫 검사는 예측과 정답을 실제 HTTP API에 저장하고 중복 방지, revision, 입력·모델 해시, 예측 ID로 연결된 이벤트 3건을 확인합니다. 둘째 검사는 같은 ID와 정답이 재시작 후 유지되는지 확인합니다. 다시 실행할 때 이전 증거를 보존하려면 보고서 파일명을 바꾸고 `-PreviousReport`에도 같은 첫 보고서 경로를 지정합니다.

이 자동 검사의 건수 `0`과 T/F `false`는 **합성 계약 검사값**입니다. 모두 `data_source=demo`로 기록되며 검증된 실제 정답, 실제 운영 관측 또는 사람의 화면 사용으로 표시하지 않습니다. 검사 ID의 정답을 수동 변경하지 않습니다. 보고서의 `remote_delivery_verified=false`는 이 검사에서 AWS를 직접 읽어 검증하지 않았다는 뜻입니다.

## 사람이 화면에서 확인할 항목

자동 검사와 별도의 새 예측 ID를 사용합니다.

1. [사용자 화면](http://127.0.0.1:18001/)에서 **샘플로 시작하기**를 누릅니다. 목표 시각 `2011-09-27T06:00:00`과 직전 168시간 이력을 확인합니다.
2. **데이터 출처**가 **실습·테스트 데이터 (학습 대상 제외)**인지 확인하고 **작업량 예측하기**를 누릅니다. 단계·확률·모델 버전·예측 ID가 보이는지 확인합니다. 확률은 보정되지 않은 모델 출력이며 정답 보장이 아닙니다.
3. 변경하지 않은 샘플의 같은 목표 시각을 [원본 평가 CSV](../artifacts/test-predictions.csv)에서 확인합니다. `actual_count=0`이므로 실제 건수 `0`을 저장합니다. 이것은 과거 데이터의 확인 가능한 정답이고, 새 운영 관측은 아닙니다.
4. **저장 상태 새로고침** 후 기본 local 모드에서는 로컬 보관 상태를 확인합니다. [로그 화면](http://127.0.0.1:18001/log-console)에서 해당 예측 ID로 입력·예측·정답이 연결되고 demo로 표시되는지 확인합니다.
5. 화면을 새로 열고 저장한 예측 ID로 조회합니다. 입력 형식 오류 안내와 입력 수정 후 이전 결과가 숨겨지는지도 확인합니다.
6. 설치 안내의 Stop→Start 절차 후 같은 예측 ID를 다시 조회합니다. 확인한 화면과 결과를 기록합니다.

## 실제 데이터와 선택적 AWS 수집

실제 데이터는 원본과 같은 시각·판매전표 집계 체계로 만든 직전 168시간 이력과 다음 목표 정각을 사용합니다. 양수 판매 거래에 해당하는 전표 건수를 세되 거래가 없는 시간은 0건으로 포함합니다. **데이터 출처**의 기본값은 실습이며, 확인한 실제 집계에 한해서 **확인된 실제 판매 집계**를 명시적으로 선택합니다. CSV 업로드·직접 편집만으로 출처가 실제 집계로 바뀌지 않으며, 샘플 버튼은 다시 실습으로 설정합니다.

대상 시간이 끝난 뒤 확인 가능한 실제 건수·단계 또는 T/F만 제출하고, **정답을 모르면 입력하지 않습니다.** 고객 이름·연락처 등 원문 개인정보는 입력에 넣지 않습니다. 한국 시각을 그대로 입력하는 것으로 원본 영국 데이터와 기준이 일치하지 않습니다.

CloudWatch를 사용하도록 별도 설정한 경우에만 `cloudwatch_sent`를 확인합니다. 이 상태는 전송 수락이며 실제 수집 완료 판단에는 같은 이벤트의 AWS 원격 JSON 대조가 추가로 필요합니다. 로컬 `/log-console` 화면은 AWS 콘솔이 아닙니다. 각자 허용된 프로필과 기존 리소스를 사용하는 방법은 [AWS 연결](AWS_SETUP.md), [필요 권한](AWS_PERMISSIONS.md)을 따릅니다. 다른 사람의 비밀번호·키·인증 캐시를 공유하지 않습니다.
