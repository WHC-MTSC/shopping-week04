# 팀원에게 전달할 테스트 안내

현재 서비스는 설치한 PC의 **http://127.0.0.1:8001/** 에서만 열립니다. 팀원 각자의 PC에서 같은 주소로 접속하면 이 서비스에 연결되지 않습니다. 같은 PC에서 차례대로 테스트하세요. 원격 접속은 별도 공유 배포나 승인된 네트워크 설정이 필요합니다.

각자 Windows PC에서 독립적으로 실습하려면 이 PR의 소스를 받거나 CI가 제공하는 소스 ZIP을 풀고, `uv`와 Node.js 20 이상을 준비한 뒤 아래 명령을 실행합니다. 프로젝트 의존성 설치·검사·서비스 실행을 자동 진행하며 자세한 준비 사항은 [배포 안내](DEPLOYMENT.md)에 있습니다.

```powershell
.\scripts\deploy-local.ps1 -Action Deploy
```

이 기본 실행은 해당 PC에 로그를 로컬 저장합니다. 중앙 AWS에 모으려면 각자 허용된 AWS 프로필로 CloudWatch 옵션을 설정해야 합니다. 다른 사람의 비밀번호·인증 캐시·키를 복사해서 공유하지 않습니다.

## 샘플로 화면과 로그 흐름 확인

1. `샘플로 시작하기`를 누르고 불러온 시각과 이력을 확인합니다.
2. `작업량 예측하기`를 눌러 단계·확률·모델 버전이 표시되는지 확인합니다.
3. 예측 ID를 기록합니다. 샘플에는 테스트용 건수·단계 또는 T/F를 입력하여 정답 저장 흐름을 확인할 수 있습니다. 이는 검증된 실제 정답이나 새 운영 데이터가 아닙니다.
4. `저장 상태 새로고침`으로 CloudWatch 수락 상태를 확인합니다. 정답을 수정한 경우 새 revision이 생기는지도 확인합니다.
5. `/log-console`에서 예측 ID로 입력·예측·정답이 연결되어 있는지 확인합니다. 이 화면은 로컬 로그 조회이고 실제 AWS 콘솔은 별도입니다.
6. 아래 기록표에 담당자와 결과를 남깁니다. AWS 관리자는 실제 CloudWatch에서 같은 예측 ID의 이벤트를 다시 확인합니다.

| 담당자 | 테스트 시각 | prediction_id | feedback_id 또는 revision | 화면·저장 결과 / 오류 |
|---|---|---|---|---|
| 직접 작성 | | | | |

담당자 이름은 이 표에서만 관리합니다. 서비스는 팀원 신원을 인증하거나 이름을 이벤트에 저장하지 않으므로 로그만 보고 담당자를 추정할 수 없습니다. 계정 비밀번호·MFA 코드·액세스 키를 공유할 필요는 없습니다.

## 실제 데이터로 테스트할 때

샘플 대신 원본 집계 체계와 같은 **직전 168시간의 시간별 판매전표 건수** CSV와 다음 목표 정각을 입력합니다. 실제 결과를 확인한 뒤 실제 건수·단계 또는 확인 가능한 T/F를 제출합니다. 정답을 모르면 임의로 입력하지 않습니다. 고객 이름·연락처 등 원문 개인정보는 CSV에 넣지 않습니다.

샘플은 `data_source=demo`로 기록되며 기본 전처리에서 제외됩니다. 이번 과거 데이터 재생·재학습 결과는 [실습 기록](REVIEW_ITERATION.md)에 있고, 팀원이 직접 테스트했다는 증거를 대신하지 않습니다.
