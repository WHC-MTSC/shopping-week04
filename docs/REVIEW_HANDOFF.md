# 서비스 정의 및 신규 수령자 배포 검토

2026-11-16 작업입니다. 이전 AWS·과거 데이터 재학습 실습과 이번 인수 배포 검증을 구분합니다.

## 정의와 개선

쇼핑몰 운영 담당자가 직전 168시간의 판매전표 집계로 다음 한 시간의 없음·보통·혼잡 단계를 예측하여 업무 준비에 참고하는 로컬 프로토타입입니다. [서비스 정의 점검표](SERVICE_DEFINITION_REVIEW.md)에 사용자·목적·시각·단위·입출력과 구현 근거를 대조했습니다. 모델이나 라벨을 변경하지 않았습니다.

- 샘플 CSV 재업로드·직접 편집이 자동으로 실데이터가 되던 화면 흐름을 수정했습니다. 기본은 실습이며 실제 집계는 명시 선택합니다. 출처를 바꾸면 이전 결과와 요청 ID를 초기화합니다.
- 저장 안내에 CloudWatch를 포함하고, 과거 성능 수치가 기본 모델의 평가임을 명시했습니다.
- 독립 설치 경로 `-InstallRoot`로 기존 서비스의 코드·DB·프로세스 상태와 분리합니다. 모든 생명주기 명령과 선택적 자동 시작은 같은 설치 경로를 사용합니다.
- `verify-service.ps1`은 실제 HTTP 예측·중복 요청·건수/T/F 정답·수정 이력·로그 연결을 검사하고, 재시작 후 같은 예측과 정답 ID의 보존도 확인합니다. 자동 진단값은 합성 `demo`이며 원격 AWS 검증 성공을 주장하지 않습니다.
- [시작 안내](GETTING_STARTED.md)에 설치 도구, 브랜치, 정상 결과, 실행 정책/포트/도구 경로 문제, 팀원 실행 결과 제출 서식을 정리했습니다.

## 검증 구분

소스·의존성·로그 DB를 분리한 작성자 PC의 신규 설치 및 GitHub Windows 실행기는 기술적 재현 검증입니다. 다른 사람이 문서만 보고 성공했다는 증거는 해당 팀원의 실행 보고서가 있어야 합니다. 팀원 Windows PC의 직접 배포·화면 사용 결과는 아직 제출되지 않았습니다.

현재 브라우저 접근 제한 때문에 화면의 직접 시각 검증은 수행하지 않았습니다. 사용자 입력 이벤트 핸들러·정적 자산·API 계약 검사를 수행하며, 새 수령자는 문서의 수동 화면 확인을 별도로 진행합니다.

실제 실행 결과 및 CI 링크는 PR 본문과 이 문서의 후속 기록에 남깁니다.
