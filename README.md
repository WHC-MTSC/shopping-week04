# 쇼핑몰 시간당 작업량 단계 예측 API

**쇼핑몰 운영자가 매 정각까지 완료된 판매전표 이력으로 앞으로 한 시간의 작업량 단계(없음·보통·혼잡)를 예측해 업무 준비에 참고하는 서비스입니다.**

## 피처와 라벨

라벨은 해당 시간의 `positive_sales_invoice_count`를 **없음(idle)=0건, 보통(normal)=1~9건, 혼잡(busy)=10건 이상**으로 변환합니다. 10건 기준은 기존 4주차 분석의 높은 작업량 구간을 따랐으며 실험 전에 고정했습니다. 실제 직원 수나 처리 시간을 측정한 기준은 아닙니다. API는 정확한 주문 건수 대신 이 세 단계를 예측합니다.

정각에 직전 시간 집계가 완료되어 있다는 가정으로 해당 정각부터 한 시간을 예측합니다. 입력은 목표 시각과 그 이전 **168시간의 연속된 실제 판매전표 건수**입니다. 운영 중에는 매시간 완료된 실제 집계를 새로 제공해야 하며, 예측값을 이력에 넣는 여러 시간 앞 예측은 평가하지 않았습니다.

학습과 API는 `workload/features.py`를 공유합니다. 시각·요일·주말 여부·월·과거 1/24/168시간 전 건수·이전 3/6/24/168시간 평균·전날/전주 같은 시각부터 3시간의 과거 평균·시간과 요일의 순환값·월중 날짜를 후보로 비교했습니다. 선택된 모델은 **확장 피처에서 월을 제외한 17개 피처**를 사용합니다. 목표 시간의 정답·매출·판매량 등 해당 시간이 끝나야 알 수 있는 정보는 넣지 않습니다.

## 성능과 선택 과정

원본 8,787행을 섞지 않고 기존과 같은 시간 경계의 60/20/20으로 나눴습니다. 제공 CSV 이전의 이력은 자체 검증할 수 없으므로 첫 168행은 이력 준비에만 사용합니다. 실제 학습 5,104행, 검증 1,757행, 마지막 평가 1,758행입니다.

| 구간 | 시작 | 끝 |
|---|---|---|
| 학습 | 2010-12-15 09:00 | 2011-07-16 00:00 |
| 검증 | 2011-07-16 01:00 | 2011-09-27 05:00 |
| 마지막 평가 | 2011-09-27 06:00 | 2011-12-09 11:00 |

건수 회귀 피처 4종과 작업량 분류 48개 후보를 검증 구간에서 비교했습니다. 회귀의 검증 ±2건 일치율은 86.91~88.67%였지만 정확한 건수 일치율은 69.55~70.75% 수준이었습니다. 이전 PR #1의 마지막 평가 ±2건 일치율도 82.37%였으므로 정확한 건수를 보장하는 서비스로 설명하지 않고, 운영 작업량 단계로 문제를 재정의했습니다.

처음 분류 비교에서는 전체 정확도 약 91%인 모델도 혼잡 재현율이 0%에 가까웠습니다. 따라서 클래스 가중치를 보정하고 월을 제외한 피처도 비교했습니다. **검증 macro F1을 우선하여 모델을 선택**하고 학습+검증으로 재학습한 뒤 마지막 평가를 수행했습니다. 선택 모델은 `extended_no_month-extra-14-balanced`이며 검증 정확도 88.39%, macro F1 0.7351입니다. 클래스별 가중치는 학습 데이터에서만 계산합니다.

| 마지막 평가 지표 | 선택 모델 | 전날 같은 시각 | 항상 없음 |
|---|---:|---:|---:|
| 세 단계 정확도 | **90.56%** | 75.88% | 63.99% |
| macro F1 | 0.8370 | 0.6568 | 0.2601 |
| balanced accuracy | 84.09% | 65.63% | 33.33% |
| 주문이 있는 시간 정확도 | **76.46%** | 54.03% | 0% |
| 혼잡 재현율 | **85.71%** | 61.13% | 0% |

**85% 목표는 전체 세 단계 분류 정확도에서 달성했습니다.** 모든 지표가 85%를 넘는다는 뜻은 아닙니다. 혼잡 정밀도는 73.93%, 보통 재현율은 68.07%라 혼잡 과대 예측과 보통 구간 오분류가 남아 있습니다. 전체 점수에는 없음 구간 63.99%가 영향을 줍니다. 검증에서 97% 이상인 후보는 없었으며, 누수를 막기 위해 시간 순서를 지키고 목표를 피처에서 제외하고 저장된 과거 피처를 실제 이력과 대조했습니다. 앞으로 97~99%가 나오면 라벨 경계 완화나 쉬운 시간대만의 평가 대신 누수·중복·클래스 분포부터 점검해야 합니다.

이 마지막 기간은 PR #1에서 이미 결과가 공개된 **역사적 벤치마크**입니다. 이번 모델 선택에는 사용하지 않았지만 완전히 새로운 전향적 검증으로 주장하지 않습니다. 결과를 본 뒤 다시 피처나 라벨을 튜닝하지 않았습니다. 실제 서비스 도입 전에는 새 점포·최근 데이터로 별도 검증해야 합니다.

전체 후보 지표는 `artifacts/validation.json`, 최종 지표는 `artifacts/metrics.json`, 시간별 예측은 `artifacts/test-predictions.csv`에 있습니다.

## 실행

[uv](https://docs.astral.sh/uv/)와 Python 3.12 이상을 사용합니다. 아래 명령은 저장소 루트에서 실행합니다. 의존성은 `uv.lock`으로 고정했습니다.

```bash
uv sync --locked
uv run --locked uvicorn workload.api:app --host 127.0.0.1 --port 8000
```

- `GET /health`: 모델 준비 상태와 버전
- `GET /metadata`: 전체 입력 벡터(`feature_names`)와 실제 트리 사용 피처(`used_feature_names`), 라벨·시각 규칙·사용 한계
- `POST /predict`: 한 시간의 작업량 단계와 `[없음, 보통, 혼잡]` 순서의 확률
- `GET /docs`: OpenAPI 사용 예시

```bash
curl -H "Content-Type: application/json" --data-binary @examples/request.json http://127.0.0.1:8000/predict
```

예측 응답 예시는 `examples/response.json`에 있습니다. 확률은 보정되지 않은 앙상블 확률이며 예측의 보장된 신뢰도로 해석하면 안 됩니다.

시각은 원본 영국 소매 데이터의 **시간대 오프셋 없는 현지 시각** 형식을 사용합니다. `Z`, `+09:00` 같은 시간대가 포함된 시각은 거부합니다. 한국 서비스의 시간을 그대로 대입하면 안 되며 시간대와 집계 체계를 맞춘 데이터로 재학습해야 합니다. 목표 시각은 정확한 정각, 이력은 오름차순으로 목표 시각의 168시간 전부터 1시간 전까지여야 합니다. 음수·소수·문자열·불리언 건수, 빠진 시간·중복 시간·현재 시간의 정답·추가 필드는 422로 거부합니다. 건수는 0~100,000의 정수이며 이는 입력 보호 한도이지 학습 범위의 보장은 아닙니다.

모델은 시작할 때 한 번 읽습니다. `artifacts/model.json`은 구조를 검증한 JSON 트리 앙상블이며 pickle/joblib를 로드하지 않습니다. scikit-learn의 float32 입력 규칙을 동일하게 적용하며, 마지막 평가 전 행에서 JSON 모델과 원 모델의 확률 오차는 약 2.7e-15였습니다. 모델 파일이 없거나 유효하지 않으면 서버 시작이 실패합니다.

인증 없이 실행하는 로컬 개발 API입니다. 외부 공개 운영에는 인증·요청 크기 제한·관측·성능 검증을 별도로 적용해야 합니다.

## 재학습과 확인

```bash
uv run --locked python train.py
uv run --locked python train.py --evaluate-test
uv run --locked pytest -q
uv run --locked ruff check .
uv run --locked ruff format --check .
uv run --locked basedpyright
```

첫 명령은 검증 결과만 생성합니다. 두 번째는 검증에서 선택한 모델을 학습+검증으로 재학습하고 모델 및 마지막 평가 결과를 생성합니다. `--evaluate-test`를 반복해 결과를 보고 모델을 고르는 방식은 새로운 검증 기간 없이 사용하면 안 됩니다. CI는 저장된 모델의 실제 벤치마크 예측 일치, API 계약, 입력 오류, 직렬화 검증과 코드 품질을 확인합니다.

## 자료 출처와 한계

`data/model-input.csv`는 2주차 `shopping-week02/result/model-input.csv`의 복사본입니다. 원본은 [UCI Online Retail](https://archive.ics.uci.edu/dataset/352/online+retail)의 2010~2011년 영국 소매 자료이며, 한 행은 연속된 한 시간 구간입니다. `positive_sales_invoice_count`는 양수 판매전표 수로 실제 상품 수량·처리 시간·직원 작업량과 동일하지 않습니다. 기존 집계 규칙에는 `BANK CHARGES` 전표 같은 항목도 포함될 수 있습니다. 이번 작업은 이 원본 정의를 유지했고 정답 및 과거 집계를 임의로 수정하지 않았습니다.

출처 SHA-256과 scikit-learn 버전, 분할 경계, 후보 설정, 평가 지표는 생성된 결과에 기록했습니다. 과거 데이터의 계절 변화와 작업량의 대리 지표라는 한계를 고려해 운영 준비의 참고용으로 사용해야 합니다.
