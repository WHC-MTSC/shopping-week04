# 팀원 테스트용 CSV

모든 파일은 `hour,count` 열을 사용하는 **과거 영국 소매 자료의 실습용 이력**입니다. 데이터 출처는 **실습·테스트 데이터 (학습 대상 제외)**로 유지하세요. 시각은 원본 현지 시각이며 한국 시각이나 UTC로 바꾸지 않습니다.

전체 CSV 업로드와 시각 탐색 안내는 **`feature/service-handoff` 개선 버전** 기준입니다. CSV 파일은 `main`에서도 받을 수 있지만, 이 기능을 사용하려면 [해당 브랜치의 실행 안내](https://github.com/WHC-MTSC/shopping-week04/blob/feature/service-handoff/docs/GETTING_STARTED.md)에 따라 실행하세요.

## 전체 이력으로 여러 시각 살펴보기

[full-history.csv](full-history.csv)는 `data/model-input.csv`의 `target_hour`와 `positive_sales_invoice_count`를 각각 `hour`와 `count`로 옮긴 파일입니다. **8,787개 데이터 행**(헤더 포함 8,788행), **193,985바이트**로 1 MB 업로드 제한 안에 들어갑니다. 모든 시각과 건수를 원본 그대로 보존했으며 시간 이동·행 추가·누락값 채우기·정답 생성은 하지 않았습니다.

| 항목 | 범위 (원본 현지 시각) |
| --- | --- |
| CSV 관측 | `2010-12-08T09:00:00` ~ `2011-12-09T11:00:00` |
| 선택 가능한 예측 시작 시각 | `2010-12-15T09:00:00` ~ `2011-12-09T12:00:00` |
| 선택 가능한 정각 수 | 8,620개 |

화면의 **CSV 예시**에서도 같은 전체 파일을 내려받을 수 있습니다. 파일을 올리면 처음 예측 가능한 시각을 선택합니다. 사용 가능한 범위에서 **예측 시작 시각**을 직접 선택하거나 **이전 1시간·다음 1시간·마지막 시각** 버튼으로 이동합니다. 화면은 선택한 시각 직전 168시간만 추출하며 예측 API에도 그 168행만 보냅니다. 원본 전체 이력은 그대로 유지되고, 목표 시각의 실제값이나 이후 관측은 예측 입력에 들어가지 않습니다. **샘플 불러오기**와 `/example` JSON은 기존 168시간 예시를 유지합니다.

실제 정답을 저장하려면 원본 CSV의 같은 시각 행에서 건수를 확인하세요. 마지막 예측 시각 `2011-12-09T12:00:00`의 실제값은 파일에 없으므로 정답을 임의로 입력하지 않습니다. 이전·다음으로 시각을 바꿔도 정답이 자동으로 입력되는 것은 아닙니다.

## 보통·혼잡 사례만 빠르게 확인하기

아래 두 파일은 각각 **연속된 168시간의 데이터 행**을 포함하므로 선택 가능한 예측 시각이 하나입니다. 헤더를 합치면 각각 169행입니다.

| 파일 | 예측 시작 시각 (원본 현지 시각) | 기본 모델 예측 | 정답 입력 실습값 |
| --- | --- | --- | --- |
| [normal.csv](normal.csv) | `2011-09-27T08:00:00` | 보통 | 실제 판매전표 1건 |
| [busy.csv](busy.csv) | `2011-09-27T10:00:00` | 혼잡 | 실제 판매전표 16건 |

## 사용 방법

1. 파일 페이지에서 **Download raw file**로 CSV를 내려받습니다.
2. 실행 중인 Hourahead 화면의 **CSV 파일 불러오기**에서 파일을 선택합니다.
3. 데이터 출처는 **실습·테스트 데이터**로 유지합니다.
4. 두 168행 파일은 위 표의 예측 시각에서 사용합니다. 여러 시각을 비교하려면 전체 이력 파일을 사용하며, 관측값의 날짜를 임의로 바꾸지 않습니다.
5. **예측 실행** 후 위 실습값으로 정답을 저장하고 같은 예측 ID의 기록을 확인합니다.

기본 모델 `77f4c9c1af34`로 보통·혼잡 예측과 저장 동작을 확인했습니다. 모델을 교체했다면 예측 결과는 달라질 수 있습니다. 이 파일은 과거 데이터 재생 실습이므로 실제 운영 자료로 표시하거나 학습에 섞지 마세요.
